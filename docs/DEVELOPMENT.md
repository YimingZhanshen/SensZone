## 0. 项目定位

一个**在线** FPS 灵敏度自动查找器。与 PSA-Source-Engine 的本质区别：

|          | PSA-Source-Engine                   | SensZone                                  |
| -------- | ----------------------------------- | ----------------------------------------- |
| 输出     | 单点"完美灵敏度"（伪精确）          | **最优区间 + 置信区间**，按任务难度分层   |
| 任务     | 15s 混合跟踪+甩枪，单样本           | **离散 flick 范式**，逐 trial 记录        |
| 指标     | 混合分数（帧率依赖、可刷分）        | MT / throughput / σ(MT) / 命中率 / 运动学 |
| 目标控制 | 尺寸距离完全随机                    | **Fitts ID 分层**（宽度×距离矩阵）        |
| 输入保真 | 默认 Pointer Lock（受 OS 加速污染） | unadjustedMovement + coalesced events     |
| 游戏支持 | 仅 CS2（yaw 硬编码）                | 多游戏换算表                              |
| 语言     | 俄/英/土/乌                         | **中文默认** + 英文                       |

预期产出示例：_"你的低 ID（近战）最优区间 25–40 cm/360，高 ID（远程）40–70 cm/360，CS2 建议 sens X（±N%），Valorant 换算 Y"_——是**任务画像报告**，不是又一个数字。

## 1. 理论依据（已核实）

以下结论均来自论文原文（KB 检索命中），作为设计锚点：

1. **最优灵敏度是 4 倍区间而非单点**：0.45–1.8 °/mm ≡ **20–80 cm/360**。单位换算：`cm/360 = 36 / (°/mm)`。
2. **ID 决定最优方向**：低 ID（近/大靶）偏好高敏，高 ID（远/小靶）偏好低敏（论文 Fig. 11）。
3. **机制**：低敏 → 视角旋转慢；高敏 → 精度下降、修正性 submovement 增多（论文 Fig. 9：submovement 数随 sens 单调上升）→ 两者都拉长 MT。
4. **指标**：`ID = log₂(D/W + 1)`（Shannon/MacKenzie），`throughput = ID / MT`；**σ(MT) 最小化同样重要**（Levene 检验，论文 4.3）。
5. **短期学习效应**：每条件丢弃**前 50%** trials（论文 Fig. 10 的逐 50-trial block 验证）。
6. **肌肉记忆迷思**：经历 32 倍 sens 范围切换后，首末 session（均为偏好 sens）表现无显著差异 → **单 session 内测多个 sens 是合法的**，这正是本工具的方法论前提。
7. **Submovement 分割参数（论文 Algorithm 1，逐字核实）**：5 阶 7Hz 低通 Butterworth 滤波 → 角速度 `v = |(δaz, δel)|/δt` → 阈值 `V_start = 8°/s`，`V_end = 4°/s`，`T_min = 80ms`（心理不应期下界）。
8. **实验参数（对标复刻）**：5 档靶宽（0.57° / 1.15° / 2.29° / 4.59° / 9.15°）× 5 档方位距离带（7–25°）+ 俯仰 0–2.8° → ID 0.83–5.50 bits；试验为静态靶离散甩枪，1.5s 超时判失败；参考靶 0.57° 白色，命中参考靶后 Shift 开始计时（排除反应时间），单击判定，单 trial 仅允许一次点击。
9. **论文局限（不得照搬的部分）**：简化场景（无武器/背景/压枪）、样本 13 人、≤1.5s 短任务、未覆盖 180° 大转身/开镜/>500mm 移动。→ 论文数值只作**先验与校准参照**，最终输出以用户本人实测为准。

## 2. 现有引擎问题清单（改造基线）

### A. 算法层

1. 评分帧率依赖：跟踪分 `score += 5`/帧（:317）、目标移动按帧累积（:360）→ 高刷屏分数与目标速度同比例膨胀。
2. 策略可刷分：跟踪命中每帧 +5 无需点击（≈300 分/s），与甩枪 +1000 混合单分数；论文证明两类任务最优 sens 不同。
3. 单样本比较：每 sens 仅 1×15s，无统计功效；论文每条件 500 trials 且丢弃前 50%。
4. 顺序偏差：固定先 LOW 后 HIGH，热身利好 HIGH，无 counterbalance。
5. 二分实现错误：`baseSens = (baseSens+low)/2`（:331）是"赢家与中点折中"而非保持 [low,high] 括号收敛；残余不确定度 ±7%，被初值锚定；平局默认走 HIGH。
6. 信号丢弃：无带符号端点误差、无 MT、无 submovement 计数——判定方向最直接的物理证据全部丢失。
7. 无 Fitts ID 控制：目标随机出现，无法按任务难度分层给建议。

### B. 输入/物理保真

8. Pointer Lock 非 raw：未用 `unadjustedMovement`；高频鼠标丢样本（未用 `getCoalescedEvents`）。
9. Method B 校准歧义：`360/(counts*0.022)` 假设拖动距离=360° 全程，未问垫宽，且受加速污染；DPI+实测 cm 是确定性计算。
10. FOV 换算错误：three.js fov 为**垂直** FOV，CS2 的 90（4:3 水平）被直接塞入 → 视野失真。
11. yaw=0.022 硬编码：无多游戏换算。

### C. 工程

12. `animate()` 定义两次（:307/:356），后者覆盖前者。
13. 阶段切换无倒计时/热身轮，sens 瞬间切换打断进行中的甩枪。
14. `spawnTarget` setTimeout 链不清理；无暂停/中止；无 localStorage 历史；Three.js r128（2021）CDN 依赖。
15. 默认俄语无中文；"±0.05–0.1 手动微调"是与测量无关的拍脑袋常数。

## 3. 方法论设计（对标论文）

### 3.1 任务范式：离散 flick（MVP 唯一任务）

单 trial 流程（v2，消除"参考靶→Shift→回中"的操作负担）：

```
① 视角自动回中（瞬间切换），白色参考靶已在准星下方，灰色测试靶预览可见
② 250ms settle → 等待准星静止（角速度 <4°/s，armed）→ 玩家开始移动的瞬间
   （角速度 >15°/s）计时自动开始——无 Shift、无反应时间惩罚
③ 测试靶变绿 → 玩家尽快甩枪 → 单击判定
④ 命中 → 记录 MT；未命中/1.5s 超时 → 失败；8s 无移动 → 判 idle 跳过
⑤ 记录：MT、命中、带符号端点误差、submovement 数、等待时长、完整 az/el 序列
```

跟踪（tracking）模块为下一个开发目标（Perlin 平滑随机靶 + RMS 偏差 + 速度互相关超前/滞后），与 flick 结果分开报告、绝不混合。

### 3.2 指标体系

| 层级 | 指标           | 定义                                  | 用途                             |
| ---- | -------------- | ------------------------------------- | -------------------------------- |
| 主   | MT             | 参考靶销毁 → 单击的时长（仅电机时间） | 核心因变量                       |
| 主   | Throughput     | `ID / MT`（bit/s）                    | 跨难度可比                       |
| 主   | σ(MT)          | 每条件下 MT 标准差                    | 稳定性（论文 4.3）               |
| 主   | 命中率         | hit / trials                          | 约束指标（论文要求 >85% 才有效） |
| 辅   | 带符号端点误差 | (准星角位置 − 靶心角位置)，度为单位   | 过冲（+）/欠冲（−）方向证据      |
| 辅   | Overshoot 比率 | 误差符号与靶方位同号的比例            | 灵敏度偏高信号                   |
| 辅   | Submovement 数 | Algorithm 1 分割计数                  | 机制解释（论文 Fig. 9）          |
| 辅   | 路径效率       | 实际角路径长 / 直线角距离             | v1.1                             |

### 3.3 灵敏度搜索策略

```
锚点 = 用户当前 sens（换算成 °/mm）
条件集 = 锚点 × {0.33, 0.5, 0.75, 1.0, 1.5, 2.25}   ← ×1.5 对数间隔，6 条件
         clamp 到 [0.3, 12] °/mm（约 3–120 cm/360，覆盖论文 32 倍范围的核心段）
每条件 = 24 trials 默认（16/24/40/60 可选；ID 分层均衡抽取）
条件顺序 = 随机（shuffle）
预处理 = 每条件丢弃前 1/3 trials（保留后 2/3，最少保留 8 个）
统计 = 池化回归 MT ~ ID 得公共斜率 β（ANCOVA）
      → 每条件调整成绩 MT* = mean(MT − β(ID − 3.0))，消除各条件抽靶难易的运气差异
      → 以 1/SE² 加权对 log2(sens) 拟合二次曲线（WLS）
      → bootstrap 置信区间（400 次，按条件分层重采样）
      → 平台检测：调整后成绩在最优档 ×1.08 以内的相邻条件区间 → "最优平台"输出
```

- 总时长估算：6 条件 × 40 trials × ~1.5s ≈ 6 分钟 + 过渡，一次性 session 可完成。
- 热身：正式测试前锚点 sens 练习 10 trials（不计入）。
- 相邻条件间 3-2-1 倒计时 + "灵敏度已切换为 X"提示；ESC 可中止，进度存 localStorage 可续测。

### 3.4 Fitts ID 分层

复刻论文 Table 3 的难度矩阵：

| 方位距离带（azimuth × elevation） | 9.15°     | 4.59°     | 2.29°     | 1.15°     | 0.57°     |
| --------------------------------- | --------- | --------- | --------- | --------- | --------- |
| 7–9° × 0–1°                       | 0.83–0.99 | 1.35–1.57 | 2.03–2.31 | 2.84–3.15 | 3.74–4.08 |
| 9–11.7° × 0–1.3°                  | 0.99–1.19 | 1.57–1.84 | 2.30–2.62 | 3.14–3.49 | 4.07–4.44 |
| 11.7–15° × 0–1.7°                 | 1.19–1.41 | 1.83–2.10 | 2.61–2.92 | 3.48–3.82 | 4.43–4.78 |
| 15–19.4° × 0–2.2°                 | 1.40–1.65 | 2.10–2.40 | 2.92–3.25 | 3.81–4.17 | 4.77–5.14 |
| 19.4–25° × 0–2.8°                 | 1.64–1.91 | 2.39–2.70 | 3.24–3.58 | 4.16–4.52 | 5.13–5.50 |

- 每个 trial 从矩阵 25 格中均衡抽取（保证每条件内 ID 覆盖均匀）。
- 分析时按 ID 三桶分层：低（0–2 bits）、中（2–3.5）、高（3.5–5.5）→ 各自的 MT-vs-sens 曲线与最优区间。
- 报告页让用户按**角色权重**（如 AWP/架点 → 高 ID 权重高；突击 → 低 ID 权重高）合成加权推荐。

### 3.5 报告输出

1. **全局最优区间**（cm/360，含 bootstrap CI）+ 推荐中心点。
2. **ID 分层画像**：低/中/高 ID 各自最优区间 + 曲线图（MT vs sens，log 轴，canvas 绘制）。
3. **多游戏换算表**：推荐 cm/360 → 各游戏 sens + eDPI（见 §4.6）。
4. **物理约束校验**：输入垫宽后，若 180° 转身所需距离 > 垫宽 45%，提示"灵敏度偏低/垫子偏小"。
5. **诊断**：端点误差符号分析（整体过冲 → 建议下调方向）、命中率、submovement 与 sens 的关系图。
6. 全程引用"区间而非单点"原则；论文数值仅作为"你落在人群最优区间的位置"参照。

### 4.2 输入层（保真核心）

```js
// 1) 尽力请求 raw input；不支持则明确警告
try {
  await canvas.requestPointerLock({ unadjustedMovement: true });
} catch {
  await canvas.requestPointerLock(); // 降级
  warn('检测到浏览器不支持原始输入，建议关闭系统鼠标加速（Windows“提高指针精确度”）');
}

// 2) 高频鼠标不丢样本（8kHz 鼠标 / 360Hz 屏）
canvas.addEventListener('mousemove', (e) => {
  for (const ev of e.getCoalescedEvents?.() ?? [e])
    ingest(ev.movementX, ev.movementY, ev.timeStamp);
});

// 3) 时间戳一律 performance.now()；视角更新按 delta-time；所有运动按角度定义
```

- 预检页清单：OS 加速提醒、驱动加速/角度捕捉提醒、建议全屏（F11）、浏览器兼容性检测（unadjustedMovement 支持与否实报）。
- 校准：默认 **DPI + 实测 cm/360 确定性计算**（列出常用 DPI 表）；拖拽 360° 法仅作可选参考并标注误差来源。

### 4.3 FOV / 纵横比（关键修正）

```
输入：游戏（决定 hFOV 基准与 yaw）+ 游戏内纵横比设置（16:9 / 4:3）+ 游戏 FOV 值
CS2：90 是 4:3 基准水平 FOV
  16:9 实际 hFOV = 2·atan(tan(45°)·16/9) ≈ 106.26°
  4:3（含拉伸，如 1920×1440）hFOV = 90°
three.js 垂直 FOV = 2·atan(tan(hFOV/2) / aspect)
靶子生成：按 (azimuth°, elevation°) 极角直接定位，与分辨率/窗口尺寸无关
```

### 4.5 核心算法

**Submovement 分割（论文 Algorithm 1 原样移植）**

```
输入：time, az, el 序列
az_f, el_f ← Butterworth(5阶, 7Hz 低通)(az, el)
v[t] ← |(δaz_f, δel_f)| / δt
遍历 t：
  在 submovement 中 且 v < 4°/s 且 t−t_start > 80ms → 结束当前 submovement
  不在 且 v > 8°/s → 开始新 submovement
输出：submovement 起止列表 → 计数、各段峰值速度
```

**区间估计**：每条件（丢弃前 50% 后）得 (sensᵢ, MT̄ᵢ, σᵢ, tpᵢ)；对 `log₂(sens)` 拟合二次模型（分 ID 桶）；最优点附近取 `MT̄ ≤ min·(1+ε)` 的区间为最优区间；bootstrap 重采样给 CI。命中率 < 85% 的条件标记低置信。

### 4.6 多游戏换算

`cm/360 = 360·2.54 / (yaw · sens · DPI)`；反推任意游戏 sens。

| 游戏                               | yaw（°/count/sens） | 状态                         |
| ---------------------------------- | ------------------- | ---------------------------- |
| CS2 / CS:GO / Source 系（Apex 等） | 0.022               | 确认                         |
| Valorant                           | 0.07                | 确认                         |

### 9.3 v1.5 采纳实现要点

**A. 左右不对称检测**：records 已有 signedErrDeg 与靶位方向（azDeg 符号）；分析层按靶位方向
分组算甩枪误差（或 adjMT）分侧中位数，差 ≥12% 判不对称；报告加分侧卡 + 教练文案
（更可能是握姿/发力习惯而非灵敏度，建议专项练弱侧）；跨轮维度挂 localStorage 历史，
单轮=状态波动、连续多轮同侧差=结构性习惯。

**B. 教练建议系统**：analysis 层新增 buildCoach(report, history)：按优先级合成 ≤4 条建议——
①数据质量（命中率/warnings/rawMode/泼枪率）②背离警示 ③不对称 ④平台与微调处方；
文案全部从已有字段推导，i18n zh/en 双份。

**C. 背离警示**：跨轮对比（同锚点同模式）时检查 adjMT 方向与 meanTp 方向是否相反——
MT 变快但吞吐量跌 = 用精度换速度的假进步，防误读。

**D. 技术备忘（未来做甩枪比/一次甩到位度时必须带上）**：竞品 flickRatio 在峰值→停顿窗口内取
投影有符号极值而非停顿点投影——快速回拉型玩家折返瞬间速度（标量）不跌破阈值，按停顿点取
会系统性低估过头量；投影极值点即真实折返点。
